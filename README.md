# NAHID Private File Host — PostgreSQL storage

هذا الإصدار يخزن محتوى الملفات نفسه داخل Supabase PostgreSQL في جدول `public.nahid_file_store` باستخدام `bytea`. لا يستخدم Fly Volume لتخزين الملفات.

## إعداد محلي دون Environment Variables

افتح `config.js` وعدّل `adminPassword` و`databaseUrl`. لا توجد حاجة إلى إعداد متغيرات بيئة. لا تضع أسراراً حقيقية في ملفات Git أو ترسل ZIP يحتوي على بيانات اعتماد.

**مهم جداً:** كلمة المرور التي سبق نشرها في المحادثة أصبحت مكشوفة. غيّر كلمة مرور قاعدة البيانات في Supabase أولاً، واستخدم كلمة مرور إدارة مختلفة تماماً. لا أدرج الأسرار المنشورة داخل المشروع.

## النشر

1. اجعل اسم `app` في `fly.toml` فريداً إن كان الاسم مستخدماً.
2. من مجلد المشروع:
   ```bash
   fly launch --no-deploy
   ```
3. تأكد أن `config.js` يحتوي بيانات الاتصال الجديدة وكلمة مرور إدارة قوية.
4. انشر:
   ```bash
   fly deploy
   ```
5. افتح `https://اسم-التطبيق.fly.dev` وسجّل الدخول.

## ميزات

- صفحة إدارة محمية بكلمة مرور.
- رفع ملفات متعددة ومجلدات.
- روابط تنزيل عبر نطاق Fly.io.
- نسخ الرابط وحذف الملف من PostgreSQL.
- إنشاء الجدول والفهرس تلقائياً عند تشغيل الخادم.
- اختبار PostgreSQL حقيقي عبر `pg` من خادم Fly.io.
- حد 20 MB لكل ملف لتقليل مخاطر تضخم قاعدة البيانات.

## ملاحظات

تخزين الملفات داخل PostgreSQL يستهلك مساحة قاعدة البيانات والنسخ الاحتياطية بسرعة، وقد لا يكون مناسباً للملفات الكبيرة أو الاستخدام الإنتاجي واسع النطاق. استخدم Supabase Storage أو R2 للملفات الكبيرة عند الانتقال للإنتاج.
